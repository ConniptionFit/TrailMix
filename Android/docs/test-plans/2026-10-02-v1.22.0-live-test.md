## 1. Hard rules for the test session

- **Never `adb uninstall`, never clear app data.** `allowBackup=false`: it destroys every real note. A signature error means the wrong key; fix the key.
- **Install only the release-key build in place** (`scripts/device-test.sh install` refuses anything else and refuses a network permission).
- **Never bypass the phone's lock.** If it locks or USB drops, ask the user to unlock or reconnect and note what was interrupted.
- **The user may be using the phone.** Screenshot before tapping; move PiP windows aside and back.
- **Do not delete the user's existing notes.** Create clearly named test notes ("TM test ...") and soft-delete only those at the end, after asking.
- **Confirm before any destructive or outward action** (merging the PR, publishing a release, pushing to `main`).
- Record evidence for every case: screenshot and/or UI dump plus the logcat file, under `Android/test-artifacts/` (gitignored).

**Stop condition:** any data loss or crash on upgrade. Stop, capture everything, report to the user before continuing.

## 9. Triage and fixing

- **Severity:** S1 = data loss, crash, merge stuck/unusable, wrong user data → fix before merge. S2 = feature visibly wrong (anchor dropped, Next Steps malformed, wrong template applied, labels mostly wrong) → fix in this session if small, otherwise file. S3 = quality/tuning (heading wording, Me/Them accuracy 60-80%, chip cosmetics) → file a To-Do row.
- **Fix loop:** reproduce → smallest fix → pure unit test where a seam exists → `./gradlew check` → `install` → re-run the failing case and its neighbours → commit (`<ID>: ...`) → push → CI green.
- Model-quality issues (Nano ignoring an instruction) belong in post-processing (`NoteShape`, `AnchorCoverage`, `StructuredSummaryPrompt`), not longer prompts. The structuring prompt's overhead cap test is 3,900 chars.
