Last updated: **2026-07-31 (v1.10.0-dev)** — **AI-05 conference/presentation note quality** (versionCode 11; built + **86 unit tests green**, *not yet device-verified*), from a user request to optimize TrailMix for taking notes at conferences and presentations. Three fixes, all of which only bite on long one-sided sessions: (1) **Whole-session coverage** — every summarization path read the transcript from the front and stopped (`merge()` at 8,000 chars ≈ 10 min of speech; `DeterministicSummary` at the first 25 sentences ≈ 3 min; `fallbackMerge` at `.take(12)` lines), so a 45-minute talk produced a note about the speaker's introduction with **nothing marking the loss** — only the *summary* was truncated, never the stored transcript, which is what made it look complete. New pure modules `data/ai/TranscriptCoverage.kt` (time windows, even sampling, bounded map-reduce chunking) + `data/ai/SummaryText.kt` (filler stripping, dedupe, greedy maximal-marginal-coverage selection, keywords); the deterministic path now sections a talk by ~7-minute window with generated headings (`15:48 – 23:40 · routing, table`), the AI path became map-reduce with per-chunk failures skipped rather than fatal. **Sessions too short to slice render exactly as before.** (2) **Source annotation** — the export discarded `SummaryBullet.source` entirely and `StructuredSummaryBody` (the default renderer since v1.9.0) showed no provenance at all, while the *Sources shown* pill was drawn on structured notes but **toggled nothing**. ## Identity & Purpose

You are an LLM IDE agent responsible for reviewing, maintaining, and extending **TrailMix** — a **local-only, security-conscious Android app** (Kotlin + Jetpack Compose) that captures live mic transcripts during calls/meetings, lets the user type rough fragments alongside, and merges both **fully on-device** into a provenance-tagged note with chat/recipe follow-ups. A good session: check reality against docs before trusting either, make a scoped change through exactly one capability module, verify it compiles (and on a device when one is attached), and leave **both the Obsidian vault and the repo** accurately reflecting what changed.

## Non-negotiable Principles
- **Documentation is mandatory after ANY change** — (1) update the owning vault note(s) per the Documentation Handoff Map, (2) update repo `README.md` if user-facing behavior/config changed, (3) commit locally and push to `github` (see Project Facts for the remote), (4) move shipped items to Complete in [[Future Improvements]] **the moment they're verified complete — same session, even mid-batch before the version ships** (tag the Complete entry `vX.Y.Z-dev` + commit hashes until the release lands, then fold it into the release row). The To-Do table must never hold a row whose Status says done: a completed row sitting in To-Do is stale data that misleads the next session's backlog parse.
- **Verify `README.md` is still accurate every session**, not only when something changes — paths, build commands, version/platform status. A stale README (e.g. a build command that no longer matches the repo layout) is a real regression even if no code changed. (Added 2026-07-15 after the `Android/` restructure — a great way for exactly this kind of drift to happen unnoticed.)
- **Local-only is the product.** Never add the `INTERNET` permission, any cloud API, telemetry, crash reporting, or analytics — these are permanently declined, not merely deferred. Any feature that "needs network" needs a redesign instead. Since v1.7.0 (INT-02) there is **no dedicated cloud-sync feature at all** — the dedicated Google Drive sync was removed by user decision (do not re-suggest it; see [[Future Improvements]]'s declined list). The honest residual nuance: the user-picked Export location is any SAF folder, and if that folder happens to be synced by another app, that app may upload the files — TrailMix itself only ever writes locally and never gains `INTERNET`. Any future export surface must stay SAF/DocumentsProvider-only, never an in-process network SDK.
- **Zero-retention audio is architectural, not policy** — no code path may ever write captured audio to disk. The recognizer consumes the mic stream in memory; keep it that way.
- **All AI stays on-device and fail-soft** — every AI consumer must produce a deterministic fallback result when Gemini Nano is absent, downloading, or erroring. The app must be fully usable with no model at all.
- **Confirm before anything disruptive or irreversible** — deleting user notes/data, changing the DB schema destructively, loosening any permission or the security posture, force-pushing (the one-time, user-authorized `main` history replacement documented in [[Future Improvements]]'s REL-05 Complete entry is done — it is not a standing exception; never force-push again).
- **Schema changes are additive** — Room migrations only add. The app holds real user notes, so `fallbackToDestructiveMigration()` is **gone**: every version bump that changes the schema ships an explicit `Migration` (see `MIGRATION_2_3` through `MIGRATION_7_8` in `di/AppModule.kt`; DB is at **v8** — v1.8.0's `MIGRATION_7_8`, unchanged in v1.9.0) and increments the DB version. Retired columns (`notes.driveFileUri`) go dormant, never dropped. Never destructive-fallback again.
- **New permissions require explicit user sign-off** and must be runtime-requested, opt-in, and justified in [[Security and Privacy]]. (v1.7.0 added no new permission.)
- Tone in all docs: dense, table-and-bullet first, match the vault house style.

**Filing new work.** Any new work item — from a user request, a bug report, or an idea — must become a new row in the To-Do table using the exact schema `| ID | Priority | Category | Item | Details | Requested |`. Model the wording on a good existing row: terse but complete: what's broken/missing, what the fix would touch, any constraint that matters.
